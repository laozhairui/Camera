# Camera 类设计与迭代说明

## 1. 项目目标

本项目旨在使用 C++ 对相机设备的打开、图像采集和资源释放过程进行封装，并通过 OpenCV 统一处理图像数据。项目面向普通摄像头功能验证，同时预留海康 MVS SDK 后端，以便将底层设备接口替换为工业相机 SDK。

由于开发阶段没有可用于测试的实际海康相机，普通摄像头后端用于验证上层接口和图像处理流程；MVS 后端的真实设备行为仍需在连接海康相机后测试。两种测试结果必须区分记录。

## 2. 整体设计

项目将上层接口与底层采集实现分离。`Camera` 类对外提供 `open()`、`getImage()`、`close()`、`isOpened()` 和 `lastError()`。内部通过 `CameraBackend` 抽象接口调用具体后端。

当前提供两种实现：

- `OpenCVBackend`：使用 `cv::VideoCapture` 访问普通摄像头。
- `MVSBackend`：使用海康 MVS SDK 的 C API 完成设备枚举、创建句柄、打开设备、关闭触发模式、开始取流、获取图像缓冲区、像素格式转换、释放图像缓冲区、停止取流、关闭设备和销毁句柄。

CMake 通过 `CAMERA_BACKEND` 选择编译哪一种后端，避免在同一次构建中强制依赖两套设备环境。

## 3. 为什么使用类封装

海康 MVS SDK 主要提供 C 风格函数接口。若业务代码直接调用这些函数，就需要了解句柄、设备信息结构体、错误码、图像缓冲区和资源释放顺序，业务代码也会与具体 SDK 紧密耦合。

将这些操作放入 `Camera` 类后，上层只需要调用少量清晰的方法即可获取 `cv::Mat`。这样可以隐藏底层实现细节，降低耦合，并让普通摄像头和海康相机尽可能共享同一套上层调用方式。

## 4. 资源管理

相机设备句柄和图像缓冲区都属于需要正确释放的资源。MVS 后端在成功取得图像缓冲区后，会在处理结束后调用 `MV_CC_FreeImageBuffer`；关闭相机时按停止取流、关闭设备、销毁句柄的顺序释放资源。

`Camera` 析构函数会调用 `close()`，以减少调用者忘记关闭设备的风险。复制构造和复制赋值被禁用，避免两个对象意外共同管理同一设备资源。

## 5. 图像数据处理

OpenCV 后端直接从 `VideoCapture` 读取图像。MVS 后端取得 SDK 图像缓冲区后，将像素格式转换为 BGR8，再复制到 OpenCV 自有内存中的 `cv::Mat`。复制后即可释放 SDK 图像缓冲区，避免 `cv::Mat` 继续引用已经归还给 SDK 的内存。

## 6. 错误处理

打开设备、开始取流、获取图像或像素转换失败时，接口返回 `false`，并通过 `lastError()` 提供错误描述。调用者应检查返回值，不应在获取失败时继续使用空图像。

## 7. 当前测试与限制

普通 Windows 摄像头后端可用于验证打开设备、连续取帧、显示图像、保存图像和退出释放流程。MVS 后端需要安装匹配版本的 SDK，并且需要真实海康相机才能完成硬件验证。未连接设备时，不应将代码编译通过或接口阅读描述为真实取图测试通过。

当前实现为单线程版本，尚未实现曝光、增益、帧率设置、设备热插拔监控和多线程采集。后续可在保证基本生命周期正确的前提下逐项增加。

## 8. AI 辅助开发与代码取舍

开发过程中使用 AI 辅助理解 SDK 调用流程、整理接口和排查编译问题。代码是否保留应以实际接口、资源生命周期和本机编译测试为依据，而不是直接接受所有生成内容。对于尚未通过真实硬件验证的 MVS 功能，文档明确标注限制，不将其描述为已完成的测试结果。
