# Camera 类设计与迭代说明

## 1. 项目目标

本项目使用 C++ 对相机设备访问流程进行封装，实现相机设备打开、图像采集、资源释放以及图像数据处理等功能。

项目设计目标是将底层相机设备接口与上层业务逻辑进行分离，使上层程序无需关心具体设备类型，只需要通过统一的 Camera 类接口完成图像获取。

由于工业相机通常通过厂商 SDK 提供 C 风格接口，因此本项目参考海康威视 MVS SDK 的调用方式，对底层设备操作进行封装，同时提供 OpenCV 摄像头后端用于功能验证。

当前测试阶段主要使用 Windows 集成摄像头验证程序流程，MVS 后端代码按照 SDK 接口完成设计，但由于缺少实际海康工业相机设备，未进行真实硬件采集验证。


## 2. 项目迭代过程

项目按照功能逐步完善，采用 Git 原子化提交方式记录开发过程。

主要迭代如下：

1. 初始化项目结构

完成 CMake 工程配置、基础目录结构以及编译环境搭建。

2. 添加海康 MVS 初始化支持

根据 MVS SDK 示例程序设计设备枚举、句柄创建以及设备生命周期管理流程。

3. 添加 OpenCV 图像采集功能

使用 OpenCV VideoCapture 实现普通摄像头采集，用于验证上层图像处理流程。

4. 完成 Camera 类抽象

设计统一 Camera 接口，将具体采集方式隐藏在后端实现中。

5. 完善运行环境与采集流程

优化程序运行方式，完善错误提示和资源释放。

6. 增加视频录制功能

使用 OpenCV VideoWriter 对连续采集帧进行编码保存，实现摄像头视频录制。


## 3. 整体架构设计

项目采用接口抽象方式，将设备控制层与应用层分离。

整体结构：

Camera

↓

CameraBackend

↓

OpenCVBackend / MVSBackend


Camera 类负责提供统一接口。

CameraBackend 作为底层抽象接口。

OpenCVBackend 使用 OpenCV 访问普通摄像头。

MVSBackend 使用海康 MVS SDK 访问工业相机。


## 4. Camera 类设计

Camera 类主要提供以下接口：

open()

用于打开相机设备。

getImage()

用于获取当前一帧图像，并转换为 OpenCV 的 cv::Mat 类型。

close()

用于关闭设备并释放资源。

isOpened()

用于判断设备当前状态。

lastError()

用于返回最近一次操作失败原因。


通过该设计，上层程序不需要直接调用底层 SDK 函数，提高了代码可维护性。


## 5. 海康 MVS SDK 封装设计

海康 MVS SDK 提供 C 风格 API，需要调用设备枚举、创建句柄、打开设备、开始取流、获取图像缓存以及释放资源等接口。

本项目将这些操作封装到 MVSBackend 中。

主要流程：

1. 枚举设备

2. 创建设备句柄

3. 打开设备

4. 开启采集

5. 获取图像缓存

6. 完成像素格式转换

7. 转换为 cv::Mat

8. 释放 SDK 图像缓存

9. 停止采集

10. 关闭设备并销毁句柄


通过封装，上层代码不需要直接依赖 MVS SDK 的具体调用细节。


## 6. OpenCV 后端设计

由于开发阶段没有可用的工业相机设备，因此使用 OpenCV 后端连接 Windows 集成摄像头进行功能验证。

OpenCVBackend 使用：

VideoCapture

完成设备打开和连续帧获取。

获取后的图像统一转换为：

cv::Mat

格式，供上层程序处理。


## 7. 图像与视频采集功能

当前程序支持：

1. 实时摄像头显示

通过 OpenCV HighGUI 显示实时图像。


2. 图片保存

按下 S 键可以保存当前帧：

capture.jpg


3. 视频录制

按下 R 键开始或停止录制。

程序通过：

VideoWriter

将连续采集帧保存为：

capture.mp4


视频录制功能使用实际摄像头进行了验证。


## 8. 资源管理

相机设备、SDK 图像缓存以及内部句柄均属于需要正确释放的资源。

项目通过 RAII 思想管理生命周期。

Camera 析构函数自动调用 close()。

同时禁止复制构造和复制赋值，避免多个对象同时管理同一个设备资源。


## 9. 错误处理

程序对于以下情况进行错误检测：

设备打开失败。

图像获取失败。

视频写入失败。

资源释放异常。


错误信息通过 lastError() 提供，方便定位问题。
