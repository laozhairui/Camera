# Camera 项目开发与迭代过程说明

我一开始做这个项目时的想法其实比较直接，就是先按照海康 MVS SDK 的示例把相机初始化和取图跑起来，再慢慢往外封装。刚开始主要关注的是设备枚举、创建句柄、打开设备、开始取流、取图和释放资源这些流程，对海康 SDK 的 C 接口并不熟，所以第一阶段先搭好了工程结构，再根据官方示例理解这些 API 的调用顺序。这个过程中我也用了 AI 帮我解释 SDK 接口、分析编译错误和梳理调用关系，但具体代码我还是会结合官方示例和自己的工程实际情况去调整。最开始的设计其实比较简单，Camera 直接处理海康 SDK 的操作，后来写着写着我发现，如果以后换成别的相机，Camera 类里面会塞进去大量海康专用代码，这样 Camera 本身就会越来越像一个“海康相机类”，和我最开始想做的通用 Camera 封装不太一样。所以这一部分是我后面重点调整的地方：我参考了 AI 给出的抽象思路，把底层相机操作拆成 Backend（后端）结构，让 Camera 负责对外提供统一接口，具体的 MVSBackend 负责海康 MVS SDK，OpenCVBackend 负责普通摄像头。现在 Camera 对外主要就是 open、getImage、close、isOpened 和 lastError 这些接口，上层程序不需要直接接触海康 SDK 的 C 接口，这样也更符合这次考核要求里“用 C++ 封装 C 语言 SDK”的要求。实际开发时遇到的一个比较麻烦的问题是我手上没有真正的海康工业相机，所以 MVSBackend 虽然按照 SDK 的生命周期和示例程序进行了封装，但没办法直接拿真实设备验证取流。为了把取图、显示、拍照和录视频这些功能真正跑起来，我一开始还尝试过在 VMware 里的 Ubuntu 使用 Windows 笔记本自带摄像头，当时能识别到 /dev/video0 和 /dev/video1，也能看到 MJPG 等格式，但实际画面出现了绿色区域、拉伸以及 YUYV 超时等问题。我用 AI 一起分析了 V4L2、USB 摄像头格式和 OpenCV 读取流程，也实际换过不同分辨率和格式测试。后来我觉得继续在虚拟机里折腾摄像头本身已经不能很好地证明 Camera 封装代码是否正确，所以没有继续把时间花在 VMware 摄像头上，而是转到 Windows 原生环境，用电脑自带摄像头通过 OpenCVBackend 做实际验证。这样做以后，Camera 的打开、连续取图和窗口显示都可以正常工作。后面我又继续补了错误处理和资源管理，例如增加 lastError() 让上层能够知道最近一次操作为什么失败，同时让 Camera 在关闭和析构时负责释放后端资源，避免调用方需要自己管理底层句柄。最后为了让项目不只是“能看到画面”，我在 main.cpp 里增加了拍照和视频录制功能，按 S 可以保存 capture.jpg，按 R 可以开始或停止录制 capture.mp4，这两个功能都已经用 Windows 集成摄像头实际跑过，照片和视频也作为项目演示材料保存下来。为了效率，我省去了很多暂时用不到的东西，比如复杂异常体系、很多没有实际需求的接口以及多线程采集。AI 确实给过我多线程采集、采集线程和处理线程分离等思路，我也理解这种设计在工业相机高帧率采集场景下的意义，但目前项目没有真实工业相机和高帧率处理需求，为了让让代码更好解释和验证，这一版先保持单线程，把最核心的封装、取图、错误处理和资源管理做好。整个过程中，我自己的思路主要是先把功能跑通，然后根据实际遇到的问题不断调整结构；AI 的作用更多是帮我理解不熟悉的 SDK、解释报错、分析摄像头问题以及提供一些设计方向，我没有把 AI 给出的代码全部照搬，而是根据项目要求和实际环境删掉了一些暂时不需要的内容，再保留真正能解决问题的部分。最后项目从最开始的工程搭建和海康 SDK 初始化，逐步增加了图像获取、Camera 类封装、Backend 抽象、OpenCV 摄像头支持、错误信息、资源管理、拍照和视频录制，这些变化也对应到了 Git 里的多次原子化提交。现在这版代码的重点不是把功能堆得特别多，而是把“底层 SDK 负责具体设备，上层 Camera 提供统一接口”的思路真正做出来，并且用现有设备把能验证的部分实际验证完成。需要说明的是，Windows 摄像头的 OpenCVBackend 已经实际测试成功，而海康 MVSBackend 目前是按照官方 SDK 接口和生命周期完成封装，由于没有真实海康工业相机，所以没有做过海康实机取流测试。在再次回头复盘时能感觉出自己的原子化提交做的并不好，但由于迫不及待地想在国庆结束前完成task5所以就没有再重头进行修改，希望见谅。
